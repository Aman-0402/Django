🤔 Why We Need Blueprints?

❌ Bad Practice (Beginner)

  • Everything inside app.py
  • Routes, models, admin, logic mixed together
  • Not scalable
  • Hard to maintain

✅ Good Practice (Intermediate / Industry)

  • Separate modules using Blueprints
  • Clean, readable structure
  • Easy teamwork
  • Django-like modularity

📌 Blueprint = Mini Flask app for a specific feature

🧱 STEP 2.4: Create App Factory

Create app/__init__.py:

from flask import Flask
 
 def create_app():
     app = Flask(__name__)
 
     # Import Blueprints
     from app.main.routes import main_bp
     from app.courses.routes import courses_bp
     from app.admin.routes import admin_bp
 
     # Register Blueprints
     app.register_blueprint(main_bp)
     app.register_blueprint(courses_bp, url_prefix="/courses")
     app.register_blueprint(admin_bp, url_prefix="/admin")
 
     return app

🧱 STEP 3.3: Create Course Model

from app import db

class Course(db.Model):
id = db.Column(db.Integer, primary_key=True)
title = db.Column(db.String(150), nullable=False)
description = db.Column(db.Text, nullable=False)
duration = db.Column(db.String(50))
level = db.Column(db.String(50))  # Beginner / Intermediate / Advanced

def __repr__(self):
    return f"<Course {self.title}>"

🧠 Understand This Model

title Course name
description Course details

level Beginner / Intermediate

🧠 Concept First: What Is a Dynamic Route?

🧱 STEP 5.1: Update Course Routes (Detail View)

app/courses/routes.py

from flask import Blueprint, render_template
from app.courses.models import Course

courses_bp = Blueprint("courses", __name__)

@courses_bp.route("/")
def course_list():
courses = Course.query.all()
return render_template("course_list.html", courses=courses)

@courses_bp.route("/<int:course_id>")
def course_detail(course_id):
course = Course.query.get_or_404(course_id)
return render_template("course_detail.html", course=course)

🔍 Important Line

Course.query.get_or_404(course_id)
  • Fetches course by ID
  • Automatically shows 404 page if not found
  • Industry best practice

🧱 STEP 6.1: Admin Blueprint Routes

app/admin/routes.py

from flask import Blueprint, render_template, request, redirect, url_for
from app import db
from app.courses.models import Course

admin_bp = Blueprint("admin", __name__)

@admin_bp.route("/")
def dashboard():
courses = Course.query.all()
return render_template("admin/dashboard.html", courses=courses)

@admin_bp.route("/add-course", methods=["GET", "POST"])
def add_course():
if request.method == "POST":
   title = request.form.get("title")
   description = request.form.get("description")
   duration = request.form.get("duration")
   level = request.form.get("level")

   new_course = Course(
       title=title,
       description=description,
       duration=duration,
       level=level
   )

   db.session.add(new_course)
   db.session.commit()

   return redirect(url_for("admin.dashboard"))

return render_template("admin/course_form.html")

🧠 Understand This Clearly

GET request

  • Shows the form

POST request

  • Reads form data
  • Creates Course object
  • Saves to database
  • Redirects to dashboard

📌 Same logic as Django views — Flask is just more explicit.

🧠 Understand the UPDATE Flow

↓
Edit Link (course_id)
↓
Pre-filled Form (GET)
↓

↓
Database Updated
↓

🧱 STEP 7.1: Add Edit Route in Admin Blueprint

Add this below add_course() in app/admin/routes.py:

@admin_bp.route("/edit-course/<int:course_id>", methods=["GET", "POST"])
def edit_course(course_id):
course = Course.query.get_or_404(course_id)

if request.method == "POST":
   course.title = request.form.get("title")
   course.description = request.form.get("description")
   course.duration = request.form.get("duration")
   course.level = request.form.get("level")

   db.session.commit()
   return redirect(url_for("admin.dashboard"))

return render_template("admin/course_form.html", course=course)

🧠 Key Points to Notice

  • get_or_404 → prevents invalid IDs and shows 404 safely
  • Same template for Add & Edit
    • Add → empty form
    • Edit → pre-filled form

📌 This is professional template reuse.

✅ STEP 8: Delete Course (Delete CRUD + Confirmation)

In this step, we complete FULL CRUD by safely deleting courses from the database using a POST-only request and confirmation.

🎯 Goal of Step 8

  • Delete a course safely
  • Use POST-only delete (best practice)
  • Add a confirmation prompt
  • Complete FULL CRUD

🧠 Concept First: How DELETE Should Work

❌ Bad Practice

<a href="/delete/1">Delete</a>
  • Deletes data via GET
  • Security risk
  • Accidental deletion possible

✅ Good Practice

  • Delete via POST request
  • Use a form submit button
  • Optional confirmation popup

🧱 STEP 8.1: Add Delete Route (Admin Blueprint)

Add this below edit_course() in app/admin/routes.py:

@admin_bp.route("/delete-course/<int:course_id>", methods=["POST"])
def delete_course(course_id):
course = Course.query.get_or_404(course_id)

db.session.delete(course)
db.session.commit()

return redirect(url_for("admin.dashboard"))

📌 Why POST only?

  • Prevents accidental deletes
  • Protects against misuse
  • Industry-standard approach
