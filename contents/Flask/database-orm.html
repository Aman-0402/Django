Database & ORM

Working with databases using Flask and ORM tools like SQLAlchemy.

📘 Topic 1: Introduction to Databases

Databases are used to store, manage, and retrieve data permanently. Every real-world Flask application depends on a database.

1️⃣ Why Do We Need a Database?

Without a database ❌

  • Data is lost when the server restarts
  • Cannot store users, posts, or records

With a database ✅

  • Data is stored permanently
  • Fast searching and retrieval
  • Used in all real-world applications

Examples of data stored:

  • Users
  • Login credentials
  • Products
  • Orders
  • Blog posts

2️⃣ What is a Database?

A database is a structured collection of data stored electronically so it can be accessed, managed, and updated easily.

Simple Example (Table):


    id   name    email
    1    Aman    aman@gmail.com
    2    Rahul   rahul@gmail.com

3️⃣ Database in Flask (Big Picture)


    User
     ↓
    Flask App
     ↓
    Database
     ↓
    Flask App
     ↓
    User

👉 Flask does not store data itself. It communicates with a database to save and retrieve data.

4️⃣ Types of Databases

🔹 SQL (Relational Databases)

  • Data stored in tables
  • Fixed schema
  • Uses SQL language

Examples:

  • SQLite
  • MySQL
  • PostgreSQL

🔹 NoSQL (Non-Relational Databases)

  • Data stored as documents (JSON-like)
  • Flexible schema

Examples:

  • MongoDB
  • Firebase

👉 Flask works with both SQL and NoSQL databases, but we start with SQL.

5️⃣ What is SQL?

SQL stands for Structured Query Language. It is used to communicate with relational databases.

SQL is used to:

  • Create tables
  • Insert data
  • Read data
  • Update data
  • Delete data

Example:


    SELECT * FROM users;

6️⃣ Database Tables – Core Concept

A database table is similar to an Excel sheet:

  • Rows → Records
  • Columns → Fields

Example: users table


    id
    name
    email
    password

7️⃣ What is ORM? (Preview)

ORM stands for Object Relational Mapper.

ORM allows us to use Python classes instead of writing raw SQL queries.

Example (ORM):


    User.query.all()

Instead of raw SQL:


    SELECT * FROM users;

👉 Flask commonly uses SQLAlchemy ORM.

8️⃣ Why Use ORM?

Without ORM ❌

  • Raw SQL everywhere
  • Error-prone queries

With ORM ✅

  • Pythonic and readable code
  • Cleaner and safer database operations
  • Faster development

📘 Topic 2: SQLite with Flask

SQLite is the easiest database to start with Flask. It is lightweight, simple, and perfect for learning database concepts.

1️⃣ What is SQLite?

SQLite is a:

  • Lightweight SQL database
  • File-based database
  • Zero-configuration database

👉 The entire database is stored as a single .db file.

2️⃣ Why SQLite for Beginners?

  • ✔ No installation required
  • ✔ Easy to use
  • ✔ Perfect for learning and small applications
  • ✔ Fully supported by Flask and SQLAlchemy

❌ Not ideal for large production applications.

3️⃣ Where SQLite Fits in Flask?


    User
     ↓
    Flask App
     ↓
    SQLite (.db file)

Example database file:


    database.db

4️⃣ Two Ways to Use SQLite in Flask

  • Raw SQLite (sqlite3) ❌ (Not recommended)
  • Flask-SQLAlchemy (ORM) ✅ (Recommended)

👉 We will use ORM, but first it is important to understand the basics.

5️⃣ SQLite Without ORM (Just for Understanding)

Basic Python Example:


    import sqlite3
    
    conn = sqlite3.connect("test.db")
    cursor = conn.cursor()
    
    cursor.execute("CREATE TABLE users (id INTEGER, name TEXT)")
    conn.commit()
    conn.close()

⚠️ We will not use this method further in the course.

6️⃣ Using SQLite with Flask (Recommended Way)

We connect SQLite to Flask using Flask-SQLAlchemy.

Database URI format:


    sqlite:///database.db

Meaning:

  • sqlite → Database type
  • /// → Current project directory
  • database.db → Database file name

7️⃣ Where Will the Database File Be Created?

If your project is:


    flask_app/
    │
    ├── app.py

The SQLite database file will be:


    flask_app/database.db

8️⃣ Why We Use SQLite Before MySQL / PostgreSQL?

SQLite MySQL / PostgreSQL
Easy setupNeeds server setup
File-basedServer-based
Learning & practiceProduction use

👉 The concepts remain the same — only the database engine changes.

9️⃣ What We’ll Do Next 🔥

In upcoming topics, we will:

  • Install Flask-SQLAlchemy
  • Define database models
  • Perform CRUD operations
  • Use database migrations

📘 Topic 3: Flask-SQLAlchemy

Flask-SQLAlchemy is the ORM that connects Flask applications with databases using Python classes instead of raw SQL queries.

1️⃣ What is Flask-SQLAlchemy?

Flask-SQLAlchemy is:

  • A Flask extension
  • Built on top of SQLAlchemy
  • Used to work with databases using Python code

👉 No need to write raw SQL queries.

2️⃣ Why Use Flask-SQLAlchemy?

Without ORM ❌

  • Manual SQL queries everywhere
  • Hard to maintain and debug

With ORM ✅

  • Tables → Python classes
  • Rows → Python objects
  • Cleaner, safer, and readable code

3️⃣ Install Flask-SQLAlchemy

Activate virtual environment:


    venv\Scripts\activate

Install package:


    pip install flask-sqlalchemy

4️⃣ Update requirements.txt


    pip freeze > requirements.txt

5️⃣ Basic Setup in Flask App

app.py


    from flask import Flask
    from flask_sqlalchemy import SQLAlchemy
    
    app = Flask(__name__)
    
    # Database configuration
    app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///database.db"
    app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
    
    db = SQLAlchemy(app)

6️⃣ What Does Each Line Mean?

SQLALCHEMY_DATABASE_URI

  • Tells Flask which database to use

    sqlite:///database.db
  • Creates a database.db file
  • Uses SQLite in the current project folder

db = SQLAlchemy(app)

  • Connects Flask application with the database

7️⃣ ORM Mapping Concept (Very Important)

ORM Concept Database
ClassTable
AttributeColumn
ObjectRow

8️⃣ What Happens After Setup?

Once Flask-SQLAlchemy is configured:

  • You can define database models
  • Flask can create tables
  • You can insert, read, update, and delete data

👉 Models come next 🔥

📘 Topic 4: Models & Tables

Models define the structure of your database tables using Python classes. They are the foundation of working with databases using Flask-SQLAlchemy.

1️⃣ What is a Model?

A model is a Python class that represents a database table.

Simple Mapping:

  • Python Class → Database Table
  • Class Variable → Table Column

2️⃣ Where Do We Write Models?

For small and learning projects, models are usually written inside: 


    app.py

👉 In larger projects, models are moved to a separate models.py file.

3️⃣ Creating Your First Model

Example: User Table


    from flask import Flask
    from flask_sqlalchemy import SQLAlchemy
    
    app = Flask(__name__)
    
    app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///database.db"
    app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
    
    db = SQLAlchemy(app)
    
    class User(db.Model):
        id = db.Column(db.Integer, primary_key=True)
        name = db.Column(db.String(100))
        email = db.Column(db.String(120))

4️⃣ Understanding Each Line (IMPORTANT)

class User(db.Model):

  • Defines a table named user (auto-generated)

id = db.Column(db.Integer, primary_key=True)

  • Primary key column
  • Auto-incremented unique ID

name = db.Column(db.String(100))

  • Text column
  • Maximum length of 100 characters

email = db.Column(db.String(120))

  • Email column

5️⃣ Common Column Types

Type Meaning
IntegerNumbers
String(n)Text
BooleanTrue / False
FloatDecimal values
DateTimeDate & time

6️⃣ Creating Database Tables

After defining models, create tables by running the following once.

Step 1: Open Python shell


    python

Step 2: Create tables


    from app import db
    db.create_all()
  • ✔ Creates database.db
  • ✔ Creates table user

7️⃣ How to Check Table Exists?

  • Check if database.db file exists
  • Open it using DB Browser for SQLite

8️⃣ Adding Constraints (Optional but Good)


    email = db.Column(db.String(120), unique=True, nullable=False)
Option Meaning
uniqueNo duplicate values allowed
nullable=FalseCannot be empty

9️⃣ Best Practice 🔥

  • ✔ Always define a primary key
  • ✔ Use proper data types
  • ✔ Use meaningful and clear column names

📘 Topic 5: CRUD Operations (Create, Read, Update, Delete)

CRUD represents the four basic operations performed on database data. Every real-world application (login systems, blogs, dashboards) relies on CRUD.

1️⃣ What is CRUD?

Operation Meaning
CreateInsert data
ReadFetch data
UpdateModify data
DeleteRemove data

👉 Every real application (login, blog, dashboard) uses CRUD operations.

2️⃣ Our Model (Recap)


    class User(db.Model):
        id = db.Column(db.Integer, primary_key=True)
        name = db.Column(db.String(100))
        email = db.Column(db.String(120))

3️⃣ CREATE – Insert Data

Create a new user:


    @app.route("/add-user")
    def add_user():
        user = User(name="Aman", email="aman@gmail.com")
        db.session.add(user)
        db.session.commit()
        return "User Added"

Important Steps:

  • Create object
  • db.session.add()
  • db.session.commit()

4️⃣ READ – Fetch Data

Fetch all users:


    @app.route("/users")
    def users():
        users = User.query.all()
        return str(users)

Fetch a single user by ID:


    @app.route("/user/<int:id>")
    def get_user(id):
        user = User.query.get(id)
        return user.name

5️⃣ UPDATE – Modify Data


    @app.route("/update-user/<int:id>")
    def update_user(id):
        user = User.query.get(id)
        user.name = "Updated Name"
        db.session.commit()
        return "User Updated"

6️⃣ DELETE – Remove Data


    @app.route("/delete-user/<int:id>")
    def delete_user(id):
        user = User.query.get(id)
        db.session.delete(user)
        db.session.commit()
        return "User Deleted"

7️⃣ Important ORM Methods

Method Purpose
add()Insert record
commit()Save changes
query.all()Fetch all records
query.get()Fetch by ID
delete()Remove record

8️⃣ Common Beginner Mistakes ❌

Mistake Fix
Forgot to commitAlways commit after changes
NoneType errorCheck if record exists
Deleting wrong dataUse ID carefully

9️⃣ Best Practice 🔥

  • ✔ Always commit after insert/update/delete
  • ✔ Check if record exists before modifying
  • ✔ Use IDs for update and delete operations

📘 Topic 6: Database Relationships

Database relationships connect tables so data can be linked properly. Relationships help model real-world data accurately in Flask applications.

1️⃣ Why Do We Need Relationships?

Without relationships ❌

  • Data duplication
  • No logical connection between tables

With relationships ✅

  • Clean database design
  • Real-world data structure

Examples:

  • One User → many Posts
  • One Course → many Students

2️⃣ Types of Relationships (Flask ORM)

Relationship Meaning
One-to-OneOne record ↔ one record
One-to-ManyOne ↔ many
Many-to-ManyMany ↔ many

👉 We start with One-to-Many because it is the most commonly used.

3️⃣ One-to-Many (Most Used)

Example:


    One User ──────> Many Posts

4️⃣ Create Parent Model (User)


    class User(db.Model):
        id = db.Column(db.Integer, primary_key=True)
        name = db.Column(db.String(100))
        posts = db.relationship("Post", backref="user")

5️⃣ Create Child Model (Post)


    class Post(db.Model):
        id = db.Column(db.Integer, primary_key=True)
        title = db.Column(db.String(200))
        user_id = db.Column(db.Integer, db.ForeignKey("user.id"))

6️⃣ Understanding Foreign Key 🔑


    db.ForeignKey("user.id")

Meaning:

  • Connects Post to User
  • user.id is the primary key of User table

7️⃣ How Relationship Works in Code

Create User:


    user = User(name="Aman")
    db.session.add(user)
    db.session.commit()

Create Post for User:


    post = Post(title="My First Post", user_id=user.id)
    db.session.add(post)
    db.session.commit()

8️⃣ Access Related Data

Get all posts of a user:


    user = User.query.get(1)
    user.posts

Get user from post:


    post = Post.query.get(1)
    post.user.name

9️⃣ Relationship Options (Optional)


    db.relationship("Post", backref="user", lazy=True)
Option Meaning
backrefAccess parent object from child
lazyControls when related data is loaded

📘 Topic 7: Flask-Migrate (Migrations)

Flask-Migrate helps you safely change your database structure over time without deleting existing data. It is an essential tool for real-world Flask applications.

1️⃣ What is a Migration?

A migration is a controlled way to update the database structure.

Migrations allow you to:

  • Add new columns
  • Modify existing tables
  • Update database schema

👉 All without losing existing data.

2️⃣ Why Migrations Are Needed?

Without migrations ❌

  • You must delete the database
  • All data is lost

With migrations ✅

  • Update tables safely
  • Track database changes
  • Industry-standard workflow

3️⃣ Flask-Migrate Uses Alembic

  • Flask-Migrate → Flask extension
  • Alembic → Migration engine

👉 You do not use Alembic directly. Flask-Migrate handles it for you.

4️⃣ Install Flask-Migrate

Activate virtual environment:


    venv\Scripts\activate

Install package:


    pip install flask-migrate

Update dependencies:


    pip freeze > requirements.txt

5️⃣ Setup Flask-Migrate in App

app.py


    from flask import Flask
    from flask_sqlalchemy import SQLAlchemy
    from flask_migrate import Migrate
    
    app = Flask(__name__)
    
    app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///database.db"
    app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
    
    db = SQLAlchemy(app)
    migrate = Migrate(app, db)

👉 Flask is now ready to manage database schema changes.

6️⃣ Initialize Migration Folder (ONE TIME)


    flask db init

This creates:


    migrations/

The migrations folder tracks database versions and changes.

7️⃣ Create a Migration

After changing a model, run: 


    flask db migrate -m "initial tables"
  • Detects model changes
  • Creates migration script

8️⃣ Apply Migration to Database


    flask db upgrade
  • ✔ Database updated
  • ✔ Existing data preserved

9️⃣ Example: Add New Column Safely

Update Model:


    class User(db.Model):
        id = db.Column(db.Integer, primary_key=True)
        name = db.Column(db.String(100))
        email = db.Column(db.String(120))
        age = db.Column(db.Integer)   # NEW COLUMN

Run migration commands:


    flask db migrate -m "add age column"
    flask db upgrade

👉 The age column is added without deleting existing data.

🔁 Migration Command Summary

Command Purpose
flask db initInitialize migrations
flask db migrateCreate migration
flask db upgradeApply migration
flask db downgradeRollback changes

🔥 Important Rules (Remember This)

  • ✔ Run migrate after every model change
  • ✔ Run upgrade to apply changes
  • ❌ Never delete the database in production
