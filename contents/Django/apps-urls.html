Function-Based Views, Apps & URL Routing

Understanding FBVs, multiple apps, and URL patterns in Django 5

Function-Based Views (FBV) in Django

A Function-Based View (FBV) is a Python function in Django that:

  • Takes an HTTP request as input
  • Performs application logic
  • Returns an HTTP response
In Django, every page you see in the browser is generated by a view.

Basic Structure of a Function-Based View

def view_name(request):
    return HttpResponse("Response")
  • view_name → Any valid Python function name
  • request → Mandatory HTTP request object
  • HttpResponse() → Sends response to browser

views.py – Practical Examples

from django.shortcuts import render
from django.http import HttpResponse

1. Simple Text Response

def myfunction(request):
    return HttpResponse("Hello Django")

2. Home Page View

def home(request):
    return HttpResponse("Home Page")

3. HTML Content Using HttpResponse

def html_view(request):
    return HttpResponse("""
        <h1 style='color:blue'>Welcome to Django</h1>
        <p>This is a Function Based View</p>
        <button>Click Me</button>
    """)
Returning raw HTML is allowed, but templates are recommended for large projects.

4. Math Operation Example

def add_numbers(request):
    a = 10
    b = 20
    result = a + b
    return HttpResponse(f"Addition Result: {result}")

5. PHP-Style Dynamic Output

def php_style(request):
    name = "Aman"
    age = 22
    return HttpResponse(f"""
        <h2>User Details</h2>
        <p>Name: {name}</p>
        <p>Age: {age}</p>
    """)

urls.py – URL Configuration

from django.contrib import admin
from django.urls import path
from app1 import views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', views.home, name='home'),
    path('myfun/', views.myfunction),
    path('html/', views.html_view),
    path('add/', views.add_numbers),
    path('php/', views.php_style),
]
Django does not auto-connect views. Every view must be explicitly mapped using path().

Key Points (Exam / Viva)

  • FBVs use Python functions
  • The request parameter is mandatory
  • HttpResponse() sends output
  • URLs are connected using path()
  • One URL → One view → One response

📘 Create Multiple Applications in Django

Django follows a modular architecture, where a single project can contain multiple applications. Each app handles a specific feature, making the project scalable and easy to maintain.

🔹 Step 1: Create Django Project

django-admin startproject main
cd main

🔹 Step 2: Create Multiple Applications

Create App 1

python manage.py startapp app1

Create App 2

python manage.py startapp app2

🔹 Step 3: Register Apps in settings.py

Open settings.py and add both apps inside INSTALLED_APPS. 

INSTALLED_APPS = [
    'app1',
    'app2',
]
📌 Without this step, Django will not recognize the apps.

🔹 Step 4: Create Views in Each App

app1 → views.py

from django.http import HttpResponse

def app1_home(request):
    return HttpResponse("Welcome to App 1")

app2 → views.py

from django.http import HttpResponse

def app2_home(request):
    return HttpResponse("Welcome to App 2")

🔹 Step 5: Connect Apps Using urls.py

Main Project → urls.py

from django.contrib import admin
from django.urls import path
from app1 import views as app1_views
from app2 import views as app2_views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('app1/', app1_views.app1_home),
    path('app2/', app2_views.app2_home),
]

🔹 Output in Browser

/app2/ Welcome to App 2

📘 URL Patterns in Django

Django uses URL patterns to decide which view function should run for a given browser URL. In short: 

Browser URL  →  View Function

🔹 What are URL Patterns?

URL patterns are defined in urls.py using the path() function. 

path('url/', views.function_name, name='url_name')

🔹 Project Structure

urlPattern/
│── manage.py
│
├── urlPattern/
│   ├── settings.py
│   ├── urls.py   ← main URL file
│
├── url1/
│   ├── views.py
│
├── url2/
│   ├── views.py

🔹 Creating Views

url1 → views.py

from django.http import HttpResponse

def learn_django(request, **kwargs):
    status = kwargs.get('status')
    return HttpResponse(f"Learning Django | Status = {status}")

url2 → views.py

from django.http import HttpResponse

def home(request):
    return HttpResponse("Welcome to URL App 2")

🔹 URL Configuration (Main urls.py)

from django.contrib import admin
from django.urls import path
from url1 import views as url1_views
from url2 import views as url2_views

urlpatterns = [
    path('admin/', admin.site.urls),

    # multiple URLs → same view
    path('learn/', url1_views.learn_django),
    path('study/', url1_views.learn_django),
    path('django/', url1_views.learn_django),

    # keyword argument
    path('learn/<str:status>/', url1_views.learn_django),

    path('home/', url2_views.home),
]

🔹 Multiple URLs for Same Function

Why use it?

  • SEO-friendly URLs
  • Backward compatibility
  • Different routes → same logic

Example:

/learn/
/study/
/django/

All the above URLs call the same view: learn_django()

🔹 Keyword Arguments in URLs

Django allows passing dynamic values from the URL using keyword arguments. 

path('learn/<str:status>/', views.learn_django)

View using **kwargs

def learn_django(request, **kwargs):
    status = kwargs.get('status')
    return HttpResponse(f"Learning Django | Status = {status}")

Example URLs:

URL status value
/learn/beginner/ beginner
/learn/advanced/ advanced
/learn/pro/ pro
Why **kwargs?
• Stores URL parameters as a dictionary
• .get() prevents KeyError
• Enables clean and dynamic URLs

🔹 Common Mistakes ❌

  • Misspelling kwargs
  • Forgetting <datatype:name>
  • Mismatch between URL parameter and view logic
  • Using positional arguments incorrectly

Final Notes

  • FBVs are ideal for learning Django fundamentals
  • Apps make Django modular and scalable
  • URLs explicitly control routing
  • Understanding FBVs is essential before CBVs
