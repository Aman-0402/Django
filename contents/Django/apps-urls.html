Function-Based Views, Apps & URL Routing

Understanding FBVs, multiple apps, and URL patterns in Django 5

Function-Based Views (FBV) in Django

A Function-Based View (FBV) is a Python function in Django that:

  • Takes an HTTP request as input
  • Performs application logic
  • Returns an HTTP response
In Django, every page you see in the browser is generated by a view.

Basic Structure of a Function-Based View

def view_name(request):
    return HttpResponse("Response")
  • view_name → Any valid Python function name
  • request → Mandatory HTTP request object
  • HttpResponse() → Sends response to browser

views.py – Practical Examples

from django.shortcuts import render
from django.http import HttpResponse

1. Simple Text Response

def myfunction(request):
    return HttpResponse("Hello Django")

2. Home Page View

def home(request):
    return HttpResponse("Home Page")

3. HTML Content Using HttpResponse

def html_view(request):
    return HttpResponse("""
        <h1 style='color:blue'>Welcome to Django</h1>
        <p>This is a Function Based View</p>
        <button>Click Me</button>
    """)
Returning raw HTML is allowed, but templates are recommended for large projects.

4. Math Operation Example

def add_numbers(request):
    a = 10
    b = 20
    result = a + b
    return HttpResponse(f"Addition Result: {result}")

5. PHP-Style Dynamic Output

def php_style(request):
    name = "Aman"
    age = 22
    return HttpResponse(f"""
        <h2>User Details</h2>
        <p>Name: {name}</p>
        <p>Age: {age}</p>
    """)

urls.py – URL Configuration

from django.contrib import admin
from django.urls import path
from app1 import views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', views.home, name='home'),
    path('myfun/', views.myfunction),
    path('html/', views.html_view),
    path('add/', views.add_numbers),
    path('php/', views.php_style),
]
Django does not auto-connect views. Every view must be explicitly mapped using path().

Key Points (Exam / Viva)

  • FBVs use Python functions
  • The request parameter is mandatory
  • HttpResponse() sends output
  • URLs are connected using path()
  • One URL → One view → One response

Creating Multiple Applications in Django

python manage.py startapp app1
python manage.py startapp app2

Register Apps in settings.py

INSTALLED_APPS = [
    'app1',
    'app2',
]

URL Patterns in Django

path('learn/<str:status>/', views.learn_django)
def learn_django(request, **kwargs):
    status = kwargs.get('status')
    return HttpResponse(f"Learning Django | Status = {status}")
kwargs enables dynamic URLs and prevents KeyError.
