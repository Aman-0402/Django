Django 5 – Architecture & Project Structure

How Django works internally, server control, and professional project & app structure

This chapter explains how Django works internally, how to run and control the development server, and how projects and applications are structured in a professional Django workflow.

Understanding this chapter is critical before learning URLs, Views, Templates, and Models.

How to Run Django Development Server

The Django development server is a lightweight web server used only for development and testing purposes.

  1. Open terminal / command prompt
  2. Navigate to your Django project folder (where manage.py exists)
  3. Run the command:
python manage.py runserver

Default Server Address

By default, Django runs on: 

http://127.0.0.1:8000/
  • 127.0.0.1 → Localhost (your own computer)
  • 8000 → Default Django port
The site is accessible only on your system, not on the internet.

How to Change Django Server Port

Sometimes port 8000 may already be in use, or you may want to run multiple projects simultaneously. 

python manage.py runserver 8080

Server will now run at: 

http://127.0.0.1:8080/

How to Stop Django Server

To stop the development server safely: 

CTRL + C

Django Project vs Django Application

Django Project

  • The entire website or system
  • Contains settings, URLs, and configurations
  • Can include multiple apps

Examples:

  • College Management System
  • E-Commerce Website
  • Learning Management System

Django Application (App)

  • A specific module inside a project
  • Handles one responsibility

Examples:

  • Authentication app
  • Blog app
  • Student management app
  • Payment app
A single Django project can contain multiple apps, each handling a different feature.

Creating a Django Application (Professional Way)

Step 1: Go to Project Directory

cd sms

Step 2: Create Django App

python manage.py startapp app1

Django App Folder Structure

app1/
│── migrations/
│   └── __init__.py
│── __init__.py
│── admin.py
│── apps.py
│── models.py
│── tests.py
│── views.py

Explanation of Django App Files

migrations/

Stores migration files and tracks database changes step by step.

__init__.py

Marks the folder as a Python package so Django can import it.

admin.py

Registers models with Django Admin for CRUD operations.

apps.py

App configuration file used internally by Django.

models.py

Defines database tables using Python classes.

views.py

Contains business logic and handles HTTP requests and responses.

tests.py

Used for writing test cases to ensure app quality and stability.

Registering Django App (Mandatory)

After creating an app, Django will not recognize it automatically. You must register it inside settings.py.

Without registering the app:
  • Models won’t migrate
  • Admin won’t show models
  • Views won’t work correctly

Django Architecture – Big Picture

  1. User sends request via browser
  2. URL matched in urls.py
  3. View processes the request
  4. Model interacts with database
  5. Template renders HTML
  6. Response sent back to user

This flow follows Django’s MVT (Model–View–Template) architecture.
