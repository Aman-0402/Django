Django Messages Framework

Show one-time success, error, and info notifications to users after form submissions and redirects.

📘 What Are Flash Messages?

Flash messages are one-time notifications shown to the user after an action — like "Profile saved!" after a form submit, or "Invalid credentials" after a failed login. They survive a redirect (stored in session) and disappear after being displayed once.

Without MessagesWith Messages Framework
Pass error/success via URL paramsStore in session, show on next page
Message visible in browser URL barClean URL, message in HTML
Manual session handlingOne line: messages.success(request, "...")
🔑 django.contrib.messages is in INSTALLED_APPS by default. No extra setup needed.

📊 Message Levels

FunctionLevelUse Case
messages.debug()DEBUG (10)Dev info only
messages.info()INFO (20)Neutral information
messages.success()SUCCESS (25)Action completed ✔
messages.warning()WARNING (30)Caution needed
messages.error()ERROR (40)Something failed ✘

🟢 Basic Usage in Views

# students/views.py

from django.contrib import messages
from django.shortcuts import render, redirect
from .forms import StudentModelForm

def add_student(request):
    form = StudentModelForm()

    if request.method == "POST":
        form = StudentModelForm(request.POST)
        if form.is_valid():
            form.save()
            messages.success(request, "Student added successfully!")
            return redirect("student_list")
        else:
            messages.error(request, "Please fix the errors below.")

    return render(request, "students/add_student.html", {"form": form})
✔ Add message before the redirect.
✔ Message is stored in session — survives the redirect.
✔ Message is consumed (deleted) after being displayed once.

📄 Display Messages in Template

Put this block in your base template so messages appear on every page automatically.

<!-- base.html (inside <body>, above main content) -->

{% if messages %}
  <div class="messages-container">
    {% for message in messages %}
      <div class="alert alert-{{ message.tags }}">
        {{ message }}
      </div>
    {% endfor %}
  </div>
{% endif %}
✔ message.tags returns the level name as a string: "success", "error", "warning", "info".
✔ Use it as a CSS class to style each type differently.

🅱️ Messages with Bootstrap

<!-- Bootstrap alert classes map directly to message tags -->

{% if messages %}
  {% for message in messages %}
    <div class="alert alert-{{ message.tags }} alert-dismissible fade show" role="alert">
      {{ message }}
      <button type="button" class="btn-close" data-bs-dismiss="alert"></button>
    </div>
  {% endfor %}
{% endif %}
⚠️ Bootstrap uses alert-danger but Django tags produce error. Fix by overriding the tag in settings (see below).

Fix error → danger for Bootstrap

# settings.py

from django.contrib.messages import constants as messages

MESSAGE_TAGS = {
    messages.DEBUG:   "secondary",
    messages.INFO:    "info",
    messages.SUCCESS: "success",
    messages.WARNING: "warning",
    messages.ERROR:   "danger",    # maps to Bootstrap's alert-danger
}

🔗 Multiple Messages at Once

def process_order(request):
    messages.success(request, "Order placed successfully.")
    messages.info(request, "You will receive a confirmation email.")
    messages.warning(request, "Stock is low — order may take 3-5 days.")
    return redirect("order_confirmation")

All three appear on the next page, in the order they were added.

⚙️ Messages in Class-Based Views

from django.contrib import messages
from django.contrib.messages.views import SuccessMessageMixin
from django.views.generic.edit import CreateView
from django.urls import reverse_lazy
from .models import Student

class StudentCreateView(SuccessMessageMixin, CreateView):
    model           = Student
    fields          = ["name", "age", "email", "course"]
    template_name   = "students/student_form.html"
    success_url     = reverse_lazy("student_list")
    success_message = "%(name)s was added successfully!"
✔ SuccessMessageMixin — adds success message automatically after form.save().
✔ %(name)s — references a form field value in the message.

📌 Messages Outside Views (Signals / Admin)

# In admin custom action — request object is available
def mark_as_django(self, request, queryset):
    count = queryset.update(course="Django")
    self.message_user(request, f"{count} students updated.", messages.SUCCESS)

🔹 Message Lifecycle

StepWhat Happens
1. View calls messages.success()Message stored in session
2. View returns redirect()Browser follows redirect
3. Next page rendersTemplate reads messages from session
4. Template displays messagesMessages cleared from session
5. Page refreshMessages gone — won't show again
🎯 Always add messages before redirect — not after. Put the display block in base.html once and every page gets it for free.
