Django templates

Understanding Django's templating system, creating and rendering templates, and using template tags and filters.

📘 Using Templates in Django (Logic vs UI)

You have created a Django project and app using: 

django-admin startproject useTemplate
  cd useTemplate
  python manage.py startapp course

🔹 Folder Structure (Important)

course/
  ├── templates/
  │   └── course/
  │       ├── django.html
  │       └── fastapi.html
  ├── views.py
  ├── urls.py   (we will create this)

🔹 Business Logic vs Representation (Very Important)

✅ Business Logic

  • Written in Python
  • Decides what data to show
  • Lives in views.py
course_name = "Django"
  duration = "3 Months"

✅ Representation (UI)

  • Written in HTML
  • Decides how data looks
  • Lives in templates
<h1>{{ course_name }}</h1>

🔹 Why Separate Logic & UI?

❌ Without Templates (Bad Practice)

return HttpResponse("<h1>Django Course</h1>")
  • Messy code
  • Hard to maintain
  • Not reusable
  • Designers cannot work easily

✅ With Templates (Best Practice)

  • Clean code
  • Easy maintenance
  • Reusable HTML
  • Industry standard
📌 Django follows MVT architecture
Model → View → Template

🔹 What is render() and Why We Use It?

The render() function connects: 

View (Python) + Template (HTML) + Data

Syntax:

render(request, template_name, context=None)
Parameter Meaning
request HTTP request
template_name HTML file path
context Data dictionary (optional)

🔹 views.py (course app)

from django.shortcuts import render
  
  def learn_django(request):
      return render(request, 'course/django.html')
  
  def learn_fastapi(request):
      return render(request, 'course/fastapi.html')
✔ No HTML inside Python
✔ Clean separation of logic & UI

📘 Render Dynamic Template in Django

Dynamic templates allow Django to send data from Python (views) to HTML (templates) and display it dynamically. 

python manage.py startapp DynamicTemplate

🔹 What is a Dynamic Template?

A dynamic template displays data coming from:

  • Database
  • Python variables
  • Calculations
  • User input
View (Python) → Template (HTML)

🔹 Ways to Render Data in Templates

  1. Using Context Dictionary
  2. Using Template Variables
  3. Using Template Tags & Filters

1️⃣ Using Context Dictionary

A context is a Python dictionary that sends data from view to template.

views.py

from django.shortcuts import render
  
  def dynamic_view(request):
      data = {
          'course': 'Django',
          'duration': '3 Months',
          'price': 5000
      }
      return render(request, 'dynamic/course.html', data)

Template (DynamicTemplate/templates/dynamic/course.html)

<h1>Course Name: {{ course }}</h1>
  <p>Duration: {{ duration }}</p>
  <p>Price: ₹{{ price }}</p>
📌 Use {{ }} to display dynamic values.

2️⃣ Using Template Variables

Template variables display values passed from views: 

{{ variable_name }}

Example:

<p>Welcome to {{ course }} Training</p>

3️⃣ Using Template Tags & Filters

Template Tags (Logic)

{% if price > 3000 %}
    <p>Premium Course</p>
  {% endif %}

Template Filters (Modify Data)

<p>{{ course|upper }}</p>
  <p>{{ course|lower }}</p>

🔹 Folder Structure

DynamicTemplate/
  ├── templates/
  │   └── dynamic/
  │       └── course.html
  ├── views.py
  ├── urls.py

🔹 Create urls.py

from django.urls import path
  from . import views
  
  urlpatterns = [
      path('', views.dynamic_view, name='dynamic'),
  ]

🔹 Connect App in Main urls.py

from django.contrib import admin
  from django.urls import path, include
  
  urlpatterns = [
      path('admin/', admin.site.urls),
      path('dynamic/', include('DynamicTemplate.urls')),
  ]

Output URL:

http://127.0.0.1:8000/dynamic/

🔹 Why Use Dynamic Templates?

  • ✔ Real-time data display
  • ✔ No hard-coding
  • ✔ Reusable templates
  • ✔ Clean architecture

🔹 Static vs Dynamic Templates

Static Dynamic
Fixed content Data changes
No Python data Python → HTML
Simple websites Real applications

🔹 Common Mistakes ❌

  • Forgetting to pass context
  • Wrong template path
  • Missing {{ }} braces
  • Not creating urls.py
  • Not registering app in INSTALLED_APPS

📘 Complete Django Template Language (DTL)

Django Template Language (DTL) is used to display dynamic data inside HTML while keeping business logic separate from presentation. Django follows the MVT Architecture: 

Model → View → Template

🔹 Why Django Uses Templates?

❌ Without Templates (Bad Practice)

return HttpResponse("<h1>Hello Django</h1>")
  • HTML mixed with Python
  • Hard to maintain
  • No reusability
  • Not industry standard

✅ With Templates (Best Practice)

  • Logic → views.py
  • UI → .html
  • Clean, reusable, scalable
📌 Templates represent the Presentation Layer.

django-admin startproject djangotemplate
  cd djangotemplate
  python manage.py startapp course

Folder Structure

course/
  ├── templates/
  │   └── course/

🔷 Basic Template Rendering

🔹 What is render()?

  • Loads an HTML template
  • Sends data (context)
  • Returns an HTTP response
render(request, template_name, context=None)

Static Template Example

from django.shortcuts import render
  
  def learn_django(request):
      return render(request, 'course/django.html')
<h1>Welcome to Django Template</h1>

🔷 Context & Dynamic Data

A context is a dictionary used to send data from views.py to templates.

Dynamic Example

def learn_django(request):
      data = {
          'name': 'Aman'
      }
      return render(request, 'course/hello.html', data)
<h1>Hello, {{ name }}!</h1>
✅ Output: Hello, Aman!

🔹 URL Connection (Mandatory)

course/urls.py

from django.urls import path
  from . import views
  
  urlpatterns = [
      path('', views.learn_django),
  ]

Project urls.py

from django.contrib import admin
  from django.urls import path, include
  
  urlpatterns = [
      path('admin/', admin.site.urls),
      path('course/', include('course.urls')),
  ]

🔷 Core Components of Django Template Language (DTL)

Django Template Language (DTL) has three core building blocks used inside .html files to display dynamic data sent from views:

  1. Template Variables
  2. Template Filters
  3. Template Tags

1️⃣ Template Variables

Template variables are placeholders used to display data sent from views.py.

Syntax

{{ variable_name }}

📌 Example 1: Single Variable

# views.py
      from django.shortcuts import render
      
      def course_page(request):
          data = {'course': 'Django 5 Mastery'}
          return render(request, 'course.html', data)
<!-- course.html -->
      <p>Course: {{ course }}</p>
🔍 Output: Course: Django 5 Mastery
✔ Django replaces {{ course }} with actual data.

📌 Example 2: Multiple Variables

# views.py
      def info(request):
          return render(request, 'info.html', {
              'name': 'Aman',
              'fees': 4500
          })
<p>Name: {{ name }}</p>
      <p>Fees: ₹{{ fees }}</p>

2️⃣ Template Filters

Filters modify how data is displayed. They do not change the original data.

Syntax

{{ variable|filter }}

🔸 Date Filter

# views.py
      from datetime import datetime
      
      def show_date(request):
          return render(request, 'date.html', {
              'today': datetime.now()
          })
<p>Date: {{ today|date:"d-m-Y" }}</p>
      <p>Time: {{ today|date:"H:i:s" }}</p>
🔍 Output: 23-12-2025 | 18:45:12

🔸 FloatFormat Filter

# views.py
      def price_view(request):
          return render(request, 'price.html', {
              'price': 123.45678
          })
<p>{{ price|floatformat:2 }}</p>
      <p>{{ price|floatformat:0 }}</p>
🔍 Output: 123.46 | 123
✔ Original value remains unchanged.

3️⃣ Template Tags

Template tags add logic inside HTML such as conditions and loops.

Syntax

{% tag %}

🔸 {% if %} Tag (Condition)

# views.py
      def fee_check(request):
          return render(request, 'fees.html', {
              'fees': 4000
          })
{% if fees > 3000 %}
        <p>Premium Course</p>
      {% else %}
        <p>Basic Course</p>
      {% endif %}
✔ Logic runs inside template without writing Python in HTML

🔸 {% for %} Tag (List Loop)

# views.py
      def courses_view(request):
          return render(request, 'courses.html', {
              'courses': ['Django', 'Flask', 'FastAPI']
          })
<ul>
      {% for c in courses %}
        <li>{{ c }}</li>
      {% endfor %}
      </ul>

🔸 Loop Counter

<li>{{ forloop.counter }}. {{ c }}</li>
Variable Meaning
forloop.counter Starts from 1
forloop.counter0 Starts from 0
forloop.first True if first item
forloop.last True if last item

🔸 Looping a Dictionary

# views.py
      def student_view(request):
          return render(request, 'student.html', {
              'student': {
                  'Name': 'Aman',
                  'Age': 22,
                  'Course': 'Django'
              }
          })
<ul>
      {% for key, value in student.items %}
        <li>{{ key }} : {{ value }}</li>
      {% endfor %}
      </ul>

✅ Quick Revision

Component Purpose
{{ variable }} Display data
| filter Modify output
{% if %} Conditional logic
{% for %} Loop data
forloop.counter Index numbers

🔹 What Templates SHOULD NOT Do ❌

  • ❌ Write Python code
  • ❌ Database queries
  • ❌ Business logic
📌 Templates are only for display logic.
