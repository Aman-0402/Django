User Profiles in Django

Extend Django's built-in User model with extra fields using a Profile model and signals.

📘 Why User Profiles?

Django's built-in User model only has basic fields — username, email, password. Real applications need more: profile picture, bio, phone number, address, etc.

The standard approach is to create a separate Profile model linked to User via a OneToOneField. Django then treats them as one combined user object.

ApproachWhen to Use
OneToOneField Profile modelMost projects — simple, keeps auth separate
Custom AbstractUserStart of project only — adds fields directly to User table
Custom AbstractBaseUserCompletely custom auth (replace username with email, etc.)
🔑 OneToOneField profile is the recommended pattern for existing projects. AbstractUser must be set before first migration — can't switch later without wiping the DB.

🟢 Step 1 — Create Profile Model

# accounts/models.py

from django.db import models
from django.contrib.auth.models import User

class Profile(models.Model):
    user    = models.OneToOneField(User, on_delete=models.CASCADE)
    bio     = models.TextField(blank=True)
    phone   = models.CharField(max_length=15, blank=True)
    avatar  = models.ImageField(upload_to="avatars/", blank=True, null=True)
    website = models.URLField(blank=True)

    def __str__(self):
        return f"{self.user.username}'s Profile"
✔ OneToOneField — one User maps to exactly one Profile.
✔ on_delete=models.CASCADE — deleting User also deletes their Profile.
✔ blank=True — field optional in forms.
✔ null=True — allows NULL in database (needed for file fields).

Run Migrations

python manage.py makemigrations
python manage.py migrate

Install Pillow (for ImageField)

pip install Pillow

⚡ Step 2 — Auto-Create Profile Using Signals

Without signals, you'd have to manually create a Profile every time a User is created. Django signals let you hook into events automatically. 

# accounts/signals.py

from django.db.models.signals import post_save
from django.dispatch import receiver
from django.contrib.auth.models import User
from .models import Profile

@receiver(post_save, sender=User)
def create_profile(sender, instance, created, **kwargs):
    if created:
        Profile.objects.create(user=instance)

@receiver(post_save, sender=User)
def save_profile(sender, instance, **kwargs):
    instance.profile.save()
✔ post_save fires after every User.save().
✔ created=True only on first save (new user), not on updates.
✔ Second signal keeps Profile in sync whenever User is updated.

Register Signals in apps.py

# accounts/apps.py

from django.apps import AppConfig

class AccountsConfig(AppConfig):
    default_auto_field = "django.db.models.BigAutoField"
    name = "accounts"

    def ready(self):
        import accounts.signals    # connect signals when app loads
# accounts/__init__.py

default_app_config = "accounts.apps.AccountsConfig"

In Views

🟡 Step 4 — Edit Profile Form

Use two ModelForms together — one for User fields, one for Profile fields.

Forms

# accounts/forms.py

from django import forms
from django.contrib.auth.models import User
from .models import Profile

class UserUpdateForm(forms.ModelForm):
    class Meta:
        model  = User
        fields = ["username", "email"]

class ProfileUpdateForm(forms.ModelForm):
    class Meta:
        model  = Profile
        fields = ["bio", "phone", "avatar", "website"]

Edit View

# accounts/views.py

from django.contrib.auth.decorators import login_required
from django.shortcuts import render, redirect
from .forms import UserUpdateForm, ProfileUpdateForm

@login_required
def edit_profile(request):
    u_form = UserUpdateForm(instance=request.user)
    p_form = ProfileUpdateForm(instance=request.user.profile)

    if request.method == "POST":
        u_form = UserUpdateForm(request.POST, instance=request.user)
        p_form = ProfileUpdateForm(request.POST, request.FILES, instance=request.user.profile)

        if u_form.is_valid() and p_form.is_valid():
            u_form.save()
            p_form.save()
            return redirect("profile")

    return render(request, "accounts/edit_profile.html", {
        "u_form": u_form,
        "p_form": p_form,
    })
✔ request.FILES — required when form has file upload (avatar).
✔ Both forms validated together — both must be valid before saving.

Edit Profile Template

<!-- accounts/templates/accounts/edit_profile.html -->

<h2>Edit Profile</h2>
<form method="POST" enctype="multipart/form-data">
  {% csrf_token %}

  <h3>Account Info</h3>
  {{ u_form.as_p }}

  <h3>Profile Info</h3>
  {{ p_form.as_p }}

  <button type="submit">Save Changes</button>
</form>
✔ enctype="multipart/form-data" — required for file uploads (avatar image). Without this, request.FILES will be empty.

🖼️ Step 5 — Serve Uploaded Avatars

# settings.py

import os

MEDIA_URL  = "/media/"
MEDIA_ROOT = os.path.join(BASE_DIR, "media")
# myproject/urls.py

from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    # ... your url patterns
] + static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
✔ MEDIA_ROOT — where files are stored on disk (media/avatars/).
✔ MEDIA_URL — URL prefix to access files in browser.
✔ static() in urls.py — serves media files in development only. Production needs a web server (nginx) to serve them.
