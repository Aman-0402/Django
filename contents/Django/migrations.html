📘 Rules to Create a Django Model

Below are the important rules you must follow while creating Django models. These rules ensure that Django ORM works correctly and your database tables are generated without errors.

📌 Example Model

from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField(unique=True)
    course = models.CharField(max_length=50)
    is_active = models.BooleanField(default=True)

    def __str__(self):
        return self.name

🔹 Rule 1: Model Must Inherit from models.Model

class Student(models.Model):

Why this is required?

  • Tells Django this class represents a database table
  • Enables ORM features
❌ Without inheritance → No table, no ORM
📌 Every Django model must inherit from models.Model

🔹 Rule 2: Model Class Name Should Be Singular & Capitalized

class Student
  • Use singular names (Student, not Students)
  • Use PascalCase
📌 Django automatically converts:
Student → students_student (table name)

🔹 Rule 3: Fields Must Be Django Model Fields

❌ Wrong

name = "Aman"

✅ Correct

name = models.CharField(max_length=100)
📌 Every attribute must be a Django Field class

🔹 Rule 4: CharField MUST Have max_length

❌ Wrong

models.CharField()

✅ Correct

models.CharField(max_length=100)
📌 Database requires a fixed size for VARCHAR fields

🔹 Rule 5: Field Names Must Be Valid Python Variables

❌ Invalid

student-name = models.CharField()

✅ Valid

student_name = models.CharField()
📌 Follow Python variable naming rules

🔹 Rule 6: Use Correct Field Type for Correct Data

age = models.IntegerField()
email = models.EmailField()
is_active = models.BooleanField()
Data Field Type
Age IntegerField
Email EmailField
Status BooleanField

🔹 Rule 7: Use Constraints Carefully

email = models.EmailField(unique=True)
is_active = models.BooleanField(default=True)
  • unique=True → Prevents duplicate values
  • default=True → Auto assigns default value
📌 Constraints ensure data integrity

🔹 Rule 8: Django Automatically Creates id Field

You did NOT write:

id = models.AutoField(primary_key=True)
✔ Django auto-adds a primary key
📌 Do NOT manually create id unless required

🔹 Rule 9: __str__() Method is Highly Recommended

def __str__(self):
    return self.name

Without __str__()

Student object (1)

With __str__()

Aman
📌 Always define __str__() for better admin readability

🔹 Rule 10: Models Must Be Inside models.py

students/models.py
📌 Django detects models only from models.py

🔹 Rule 11: App Must Be Registered in INSTALLED_APPS

INSTALLED_APPS = [
    'students',
]
❌ Not registered → No migrations, no table
📌 App must be added to INSTALLED_APPS

🔹 Rule 12: Run Migrations After Model Creation

python manage.py makemigrations
python manage.py migrate
📌 Every model change requires migrations

🔹 Rule 13: One Model = One Table (Generally)

class Student(models.Model):

This creates:

students_student
📌 Each Django model maps to one database table
🎯 Follow these rules and Django ORM will work smoothly, safely, and professionally.
